# 미리보기 초기 화질 상한과 두 창 재생 검증

2026-10-11. 로컬 시험판 2.13.3의 초기 화질 상한 보완을 검증했다. 관찰한 공개 방송에서는 기존 약 18초 지점의 버퍼 오류가 재현되지 않았으며, 별도 Chrome 창 두 개의 미리보기도 독립적으로 재생됐다. 이 결과는 모든 방송과 네트워크 조건의 무중단 재생이나 전체 배포 준비 완료를 뜻하지 않는다.

## 수정과 코드 검증

`web/preview.js`의 `MANIFEST_PARSED`에서 기존 시작 화질을 유지하면서 `startLoad()` 전에 `autoLevelCapping`을 설정한다. 이미 더 낮은 상한이 있으면 0을 포함해 그대로 보존한다. 표시 후에는 HLS의 크기 기반 자동 조절이 상한을 갱신하며, `currentLevel`로 화질을 수동 고정하지 않는다. 유효한 높이가 없는 목록의 기존 설정은 변경하지 않는다.

새 검사 세 개는 수정 전 상한 -1 또는 3이 남아 예상 실패했다. 수정 후에는 숨은 영상의 초기 상한, 기존 0과 1 상한, 이후 자동 상한 변경과 복구, 높이 없는 목록의 -1과 0을 검사했다. 전체 Node 테스트 308/308, 소스와 dist 패키지 검사, Chrome 빌드가 통과했다. 소스와 dist 및 두 설치 탭의 실제 로드된 미리보기 스크립트 SHA256은 모두 `9315a8ee950075dd710321a5cef8432e32be35e1c5283e700fd5e8f3bba1d196`이다.

Astra max의 읽기 전용 동작 검토에서 Critical과 Important 사항은 없었다. 실제 포함된 HLS 1.6.16을 사용한 검토자의 메모리 내 검사에서 시작 화질 2와 기존 상한 -1, 0, 1, 3의 첫 조각 선택은 각각 2, 0, 1, 2였다. 표시 크기가 커지면 자동 상한도 다시 올라갔다. 실제 크기 컨트롤러와 첫 조각 선택의 계약을 영구 테스트로 추가하는 것은 비차단 후속 권장 사항이다.

## 단일 미리보기 관찰과 조건

계춘회 방송 페이지의 사이드바에서 풍월량과 김뿡 방송을 검사했다. 0.1초 지연, 너비 400px, 저장된 볼륨 50%를 유지하고 검사 페이지의 시작 음소거 해제만 임시로 끈 상태였다.

첫 방송은 480p로 시작해 재생 시간 약 18.49초에서 360p로 전환됐으며, 그 전환에서 `waiting`, 버퍼 오류 또는 복구가 기록되지 않았다. 첫 추적 전체에는 약 53.5초 시점의 재진입이 한 번 있어, 그 전체 구간을 단일 연속 재생으로 분류하지 않는다. 두 번째 방송은 약 39.28초 재생까지 재진입과 오류 없이 480p에서 360p로 전환됐다.

이 단일 검사 단계에는 검사 도구의 포커스 보정이 켜져 있었다. 따라서 두 숨은 탭이 실제로 동시에 보였다는 근거로 사용하지 않는다. 다음 두 창 검사는 보정을 명시적으로 끈 별도 조건이다.

## 실제 두 창 동시 재생

사용자가 두 검사 탭을 다른 Chrome 창으로 분리했다. 양쪽 `Emulation.setFocusEmulationEnabled`를 false로 설정했다. 큰 창이 작은 창을 완전히 가리면 숨김으로 바뀌었으므로 작은 창을 앞에 두었다. 두 페이지 모두 실제 `document.visibilityState`가 visible인 상태에서 사이드바 hover를 시작했다. 창 위치와 외부 크기도 서로 달랐다.

계춘회 페이지에서는 풍월량 미리보기를, 풍월량 페이지에서는 계춘회 미리보기를 동시에 재생했다. 약 74초 추적 결과는 다음과 같다.

| 검사 | 재생 시간 | 총 영상 프레임 | 오류와 재시작 | 드롭 프레임 |
| --- | --- | --- | --- | --- |
| 계춘회 페이지의 풍월량 미리보기 | 0.69초에서 73.69초 | 24에서 2214 | 없음 | 0 |
| 풍월량 페이지의 계춘회 미리보기 | 0.63초에서 73.63초 | 22에서 2212 | 없음 | 0 |

양쪽 모두 360p, readyState 4, paused false였다. 이미 측정 가능한 크기에서 시작했으므로 480p로 시작할 의무는 없으며, 더 낮은 크기 상한을 보존한 결과와 일치한다. 첫 창의 검사 페이지 볼륨을 25%로 바꾸자 해당 영상만 0.25로 바뀌고 다른 창은 0.5를 유지했다. 소리는 검사 내내 음소거했으므로 주관적 음질 검사로 분류하지 않는다.

첫 창에서 커서를 밖으로 옮기자 소유 미리보기 영상이 제거되고 패널이 숨겨졌다. 해당 검사 탭을 닫은 뒤에도 다른 창은 90.15초와 2708프레임에서 124.35초와 3734프레임까지 계속 진행했다. 최종 오류는 null, 드롭 프레임은 0이었으며 수집된 페이지 경고와 오류 로그도 0건이었다. 이는 해당 탭에서 수집된 로그 결과이지 Chrome 확장 관리 화면의 과거 오류 전체를 검사한 결과는 아니다.

## 복원과 남은 경계

검사 페이지의 시작 음소거 해제는 원래 true로, 변경한 페이지 볼륨은 50%로 복원했다. 진단 타이머와 검사 전용 관찰자를 중단하고 검사 탭 두 개를 닫았다. `chrome.storage`에는 쓰지 않았고 사용자의 기존 시청 탭은 변경하지 않았다.

다중 페이지 재생의 독립성과 두 설정 화면의 저장 충돌은 별개다. [다중 탭과 창의 설정 저장 충돌 방지 설계](../specs/2026-10-11-multi-window-settings-design.md)는 초안이며 구현 계획 승인 전이다. 별도 HLS 보안 검토의 미완료 상태도 유지한다. 이번 초기 화질 검토와 재생 검증으로 그 보안 검토를 대체하지 않는다. 새 PR, 스토어 업로드, 릴리즈 공개는 하지 않았다.
