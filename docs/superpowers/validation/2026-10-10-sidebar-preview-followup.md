# 사이드바 미리보기 후속 수정과 검증

2026-10-10. 사용자 승인 범위는 사이드바 외 확장 미리보기 제거, 미리보기 끊김·볼륨·초기 화질 조사, 플레이어 넓은 화면 ON→OFF 후 팔로잉 자동 펼치기 보완, 화면 채우기 설명, Chrome 확장 오류 정리다. 독립적인 공격적 검토를 함께 수행한다.

## 브랜치와 배포 경계

병합된 포크 main `d5f268d84fa64b6fffbdf2c309235476fc89e6e7`에서 기존 폴더의 `codex/sidebar-preview-followup`을 만들었다. 기준 전체 테스트는169/169였다. 후속 로컬 시험판은2.13.3이다. 공개된2.13.2 릴리즈 ZIP, 원본 PR #81과 `codex/chzzk-compatibility-recovery`, 심사용 개인정보처리방침을 제공하는 `codex/community-store-preview`는 변경하지 않는다. 새 PR·스토어 업로드·심사 제출·릴리즈 공개는 이번 단계에서 수행하지 않는다.

## 원인과 실제 관찰

합성 실행에서 재생 중 볼륨5→25% 변경이5%에 남는 문제, 같은 팔로잉 더보기 버튼이 접혔는데 클릭 시도 이력만으로 준비됨이 되는 문제, 구조 교체 후 수동 접기를 잊는 문제를 확인했다. 사이드바에서 이미 연결된 anchor를 홈으로 이동해도 미리보기 요청이 발생하는 경로도 독립 검토에서 재현했다.

기존 설치본의 한 공개 방송 미리보기에서 Chrome의 `canPlayType('application/vnd.apple.mpegurl')`는 `maybe`, 포함된 HLS.js1.6.16 지원은true였다. 기존 코드는 네이티브 경로를 먼저 선택했다.12초 추적 중 media 생성 이후 재생시간0, 해상도0, readyState0, 버퍼0이 유지되고 제한 상태로 종료됐다. 따라서 `maybe`만으로 네이티브 재생을 우선하는 경로를 보완한다. 이 관찰은 모든 간헐적 끊김의 원인을 확정하거나, 수정본의 실방송 성공을 증명하지 않는다.

실제 플레이어는 넓은 화면에서 사이드바를 제거하고 좁은 화면 복귀 후 다시 표시했다. 한 차례 복귀 후 팔로잉 목록은 펼쳐졌으므로 해당 시도에서 사용자 증상을 항상 재현했다고 주장하지 않는다. 재사용된 버튼·클래스만 바뀌는 모드 전환·늦은 native 상태 변경을 별도로 회귀 검사한다. 검사에 사용한 기존 방송 탭의 화면 모드는 원래 넓은 화면으로 복원했다. 음량·Gain·확장 옵션은 변경하지 않았다.

## 수정 내용

- `preview.show` 진입과 모든 비동기 유효성 검사에서 현재 사이드바 소속을 요구한다. main 카드 hover·native video 우클릭 조작을 제거한다. `customPreview` 저장값은 정규화 시 무시하고 팝업에서 제거한다. 사이드바의 우클릭 음소거 전환은 유지한다.
- 영상은 설정된 볼륨으로 음소거 상태에서 시작한다. 설정 변경은 현재 영상의 볼륨만 바꾸며 음소거 상태는 보존한다.0%도 유지한다.
- 가능한 경우 포함된 HLS.js를 먼저 사용하고 네이티브 HLS는 대체 경로로 남긴다. 첫 조각 로딩 전 표시 크기를 고려한 시작 화질을 고르되 `currentLevel` 수동 고정을 하지 않는다. 목록 순서에 의존하지 않으며 이후에는 크기 기반 자동 화질 조절을 유지한다.
- 보통의 비치명적 오류는 HLS.js 자체 정책에 맡긴다. 치명적 media/network 복구는 hover 전체에서 최대2회이고401/403은 재시도하지 않는다. 지연된 callback과 play promise는 소유 영상·backend·hover 세대·재생 시도를 검사한다. DOM media 오류가 HLS 오류 처리보다 먼저 backend를 파괴하지 않게 한다.
- 초기 미디어 대기는15초로 제한한다. 재생 시작 후 음소거 여부와 관계없이 진행 시간이10초간 멈추면 무한 재시작 대신 영상 재생을 중단하고 썸네일/제한 상태로 전환한다. `waiting` 하나만으로 원인을 단정하지 않는다. 재생 대기·진행 시각·버퍼·해상도·오류 코드 진단은 페이지 메모리의 최근20건만 유지하며 스트림 URL·응답 원문을 남기지 않는다.
- 팔로잉 자동 펼치기는 native 상태를 확인한 후 준비됨으로 표시한다. 공개 aria-label로 compact 영역도 식별한다. native 플레이어 모드 변화를 관찰하고 모드별로 제한된 펼치기 기회를 주되, 직접 클릭·키보드 조작으로 접은 사용자 의도는 owner 세대 변경을 넘어 보존한다. 옵션 OFF→ON은 새 자동 펼치기 요청으로 처리한다.
- 화면 채우기는 플레이어 영역 높이 제약을 완화하는 기존 스타일이며 전체화면·영상 crop/zoom·화질 변경 기능이 아니다. 한국어/영어 설정 설명을 추가하고 기본 상태·저장 키는 유지한다.
- Chrome manifest는 MV3 service_worker만 선언하고 Firefox용 background/metadata는 별도 overlay와 `dist-firefox`로 출력한다. Chrome 패키지 검사는 background.scripts/page/persistent와 Firefox 전용 metadata를 거부한다. source/dist 및 두 브라우저 패키지의 권한은 확대하지 않는다. Firefox 출력 검사는 Firefox 실제 설치본 검증이 아니다.

## 독립 검토와 후속 보완

고정된 변경 `d5f268d..7ab9791`의 읽기 전용 공격적 검토에서 Critical0/Important5를 확인했다. 검토자는 해당 범위의 선택 검사92건과 추가 in-memory 재현을 실행했다. 전체198건 및 native 렌더링 결과는 구현자의 실행 결과와 구분한다. 첫 검토 판정은 수정 요청이며 설치본 승인이 아니다.

Important 항목은0초의 HLS media 복구 후 로딩 재시작 누락, 버튼 교체마다 새 기회를 주는 팔로잉 클릭 반복, readyState2에서 끝나지 않는 play promise의 시작 제한 누락, paused 상태가 진행 시간으로 취급되는 문제, 무관한 메뉴/no-op 클릭을 수동 접기로 오인하는 문제다. 후속 실패 재현6건을 확인했고,10초 위치 HLS 복구는 기존 정상 대조 사례로 통과했다.

복구 검사에는 실제 포함된 HLS.js의 recoverMediaError 메서드를 실행해0/10초의 detach/attach/startLoad 계약을 확인했다.0초에서는 명시적으로 로딩을 다시 시작하고,0초가 아닐 때 라이브러리의 재시작을 중복 호출하지 않는다. 시작 성공 여부로15초를 제한하고, paused를 새 진행으로 세지 않는다. 팔로잉 클릭은 DOM 교체를 포함해 모드/옵션 epoch 전체에서 최대2번이며, 제어 버튼의 identity와 native 상태 변화가 확인돼야 사용자 접기 의도로 기록한다. 상태 확인 대기는200ms로 제한한다.

추가 회귀는401/403, 같은 hover 복구 전의 오래된 play 거부, 지연 network 복구 중 이탈, 해상도 metadata가 없는 목록, 실제 section-fold 버튼과 다른 메뉴 구분, 키보드 형태의 click을 포함한다. 이 click 검사는 합성 DOM 계약이며 설치본의 실제 키보드 입력 성공을 뜻하지 않는다.

package 검사는 특정 Chrome MV3 선언·브라우저별 배경/metadata·참조 파일·버전 계약을 검증한다. 브라우저 공식 manifest schema 전체 검증이나 Firefox 설치 인증으로 확대하지 않는다. 보완한 변경도 고정된 새 커밋으로 재검토하며, 새 판정과 설치본 결과를 받은 뒤 최종 상태를 기록한다.

두 번째 독립 검토는 `7ab9791..f0c8cc3`에서 기존 Important5건의 보완과 집중 검사37/37을 확인했다. 추가 Critical0/Important2는 전역 접기 확인 후보의 만료 타이머가 이전 owner와 함께 폐기되는 문제,200ms를 넘는 native 상태 반영을 버려 수동 접기를 잊는 문제다. 후자는250ms 지연 합성 사례이며 실제 치지직의 고정 지연을 측정한 결과가 아니다.

두 신규 검사는 각각 기존 코드에서 예상 실패를 확인한 뒤 보완했다. 새 owner는 최초 마감 시각까지 남은 확인 시간만 이어받는다. 능동 대기가 끝나도 동일 버튼·동일 모드/옵션 epoch의 늦은 상태 변화는 수동 조작의 확인 근거로 남긴다. 이 수동 근거는 WeakRef로 보관하며 타이머나 제거된 DOM을 유지하지 않는다. 마감 이후 다른 버튼·모드 변경·옵션 변경에는 적용하지 않는다.200ms는 자동 펼치기를 막는 능동 대기의 상한이지 native 사용자 조작 인정의 시간 제한이 아니다.

이 보완 후 집중39/39, 전체 Node213/213(실패0/skip0), Chrome 스타일108/108·영상필터17/17·한영 팝업2/2를 새로 실행했다. Chrome/Firefox 빌드 및 package 검사 각각v2.13.3/20 entry resources도 통과했다. 새 고정 변경 `f0c8cc3..972625e`는 독립 재검토한다. 실제 설치본 재생·음질·초기 화질·모드 전환과 오류 로그의 미확인 상태는 그대로다.

최종 독립 재검토는 위 고정 범위에서 집중39/39를 직접 실행하고 두 P2 보완을 확인했다.50/100/150ms의 owner 반복 교체에도199ms에는 펼치기0회, 최초200ms에는1회로 마감이 연장되지 않았다. 마감 이후 다른 버튼 교체와 모드 epoch 변경도 오래된 근거를 인정하지 않았다. 해당 delta에 Critical/Important 차단 사항은 확인되지 않았으며 정적 승인으로 판정했다. 전체213건·합성 렌더링·빌드는 구현자가 확인한 결과와 구분한다.

잔여 경미한 한계: 동일 버튼·동일 epoch에서 passive 근거가 남아 있는 동안, no-op 사용자 클릭 뒤 별개 원인으로 native 상태가 바뀌면 수동 의도로 해석할 수 있다. 검토자는1초 후 별도 상태 변경 합성 사례로 이를 확인했지만 실제 치지직이 해당 순서를 발생시키는지는 확인하지 않았다. 동일 제어 identity는 연관 근거이지 인과관계 증명이 아니며, 설치본 검증에서 native 상태 변경을 함께 관찰한다. 이 정적 승인은 출시 승인이나 실방송 정상 확인이 아니다.

## 설치본 검증 대기

사용자가 `chrome://extensions`에서 기존 로컬 unpacked 시험판(`C:\Users\User\Documents\GitHub\cheese-knife\dist`)을 새로고침하고2.13.3을 확인해야 한다. 보호된 확장 관리 페이지를 우회 조작하거나 스토어 설치본을 로컬 빌드로 임의 교체하지 않는다. 필요한 사용자 개입 단계에서 진행을 멈춘다.

이후 공개 방송 페이지를 다시 로딩해 다음을 확인한다. 검사 전 상태를 기록하고 변경한 화면 모드·옵션·볼륨은 복원한다.

- 홈 카드의 native 미리보기·오디오·우클릭은 그대로이고 확장 영상은 사이드바에서만 시작되는지 확인한다.
- 사이드바 영상의 연속 재생·초기 해상도·자동 화질 변화와 대기/버퍼/재생시간을 관찰한다. 정상 방송과 권한 제한을 구분하고 URL·응답 원문·채팅·개인 정보를 증거에 저장하지 않는다.
- 우클릭 음소거 해제와 설정 볼륨 적용을 확인한다. 자동 재생 정책 때문에 시작 시 음소거하는 동작을 볼륨 오류로 오인하지 않는다. 들리는 음량·음질은 사용자 실청 확인이 필요하다.
- 플레이어 넓은 화면 ON→OFF를 반복하고 자동 펼치기·수동 더보기 접기·section 접기가 서로 충돌하지 않는지 확인한다.
- 화면 채우기 설명과 실제 높이 제약 완화 동작을 확인한다. Chrome 새 오류는 기존 기록과 구분해 검사하며 보호된 확장 오류 화면 확인이 필요하면 사용자에게 요청한다.
