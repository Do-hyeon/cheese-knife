# 다중 창 설정 구현 최종 검토

2026-10-11. Astra max가 설정 전용 범위 `0e64087..1e478b0`를 독립적으로 읽기 전용 검토했다. Critical은 없고 Important 1건, Minor는 없었다. 해당 Important는 한 번의 테스트 우선 수정 패스로 처리했으며 집중 38/38, 전체 408/408 검사가 통과했다. 수정된 설치본에서는 공통 설정 동기화와 원래 탭만 적용되는 동작, 폰트 0 복원을 확인했다. 일부 실환경 검증과 별도 HLS 작업은 남아 있으며 작업 전체 완료나 병합·릴리즈 준비 완료 판정은 아니다.

## 지적과 수정

`styles.js`는 대상 페이지 새로고침 응답을 받은 시점의 화면 값을 적용 완료 목록으로 복사했다. 응답 대기 중 같은 화면에 입력하거나 다른 설정 화면에서 저장하면, 이전 revision으로 한 번 새로고침한 페이지에 최신 스타일까지 적용한 것으로 취급해 추가 적용 버튼이 사라졌다. 후속 CSS 등록 실패 뒤 재적용하는 경우도 동일했다.

broker의 성공 reload 응답에 그 작업의 정규화된 `appliedStyles`를 추가하고 스타일 화면은 이 목록만 적용 완료 기준으로 삼도록 수정했다. 알 수 없는 저장 필드는 그대로 보존하지만 응답에는 포함하지 않는다. 해당 목록이 없는 응답은 화면 값을 대신 복사하지 않는다. 저장 키·권한·요청 action은 변경하지 않았다.

실제 생산 HTML·client·broker 검사에 reload 대기 중 로컬 입력, 다른 화면 저장, 후속 CSS 실패 후 재적용의 세 순서를 추가했다. broker의 응답이 이후 저장과 무관하게 해당 작업의 알려진 스타일만 반환하는 검사도 추가했다. 네 검사를 먼저 실패시키고 수정 후 통과시켰다. 처음 수정 후 Node와 jsdom 배열 prototype 비교 때문에 내용이 같아도 실패한 검사는 Node 배열로 변환해 리터럴 내용 검증을 유지했다. 최종 전체 검사는 408개, 실패·취소·skip은 모두 0이다. 독립 검토자가 직접 실행한 수정 전 설정 관련 120개 검사도 모두 통과했다. 최종 수정 뒤 별도 재검토는 하지 않았다.

## 검토에서 판단하지 않은 범위와 처리

- 미커밋 HLS 후보 세 파일: 이 설정 범위에서 제외하고 별도 미완료 작업으로 유지한다. 잘못 포함하면 보안 검토를 받지 않은 후보를 승인한 것으로 오해할 수 있다.
- HLS 파서·초기 화질·전체 player layout·채팅 root: 설정 저장과 수명 관리 검토를 제품 전체 검증으로 확대하지 않는다. 누락된 기존 기능 오류가 있을 수 있다.
- 설치본의 필드 보존·빠른 slider·font 0→8→0·대상 적용·설정 복원: 검토 당시 미확인이었다. 이후 사용자 동기화·원래 탭만 적용·설정 복원 확인과 직접 관찰한 font 0→8→0만 실환경 결과로 기록했다. 정확한 빠른 입력 순서는 미확인으로 유지한다. 실제 타이밍 문제를 자동 fixture만으로 놓칠 수 있다.
- 동시에 보이는 실제 두 창과 실제 디코딩·음질: 두 실제 탭의 재생 진행과 peer 종료 관찰만 인정한다. 다른 창 포커스나 음질 문제는 인증하지 않는다.
- 실제 worker 재시작·BFCache persisted 수용·최소 Chrome 및 Firefox 설치: API 경계 fixture 통과와 실환경 미검증을 구분한다. 브라우저별 수명 차이는 남은 위험이다.
- tabs.get과 reload 사이 사용자 이동: 승인된 비원자적 API 한계를 유지하며 다른 활성 탭을 대신 선택하지 않는다. 아주 짧은 구간의 이동은 차단하지 못한다.
- 외부 직접 storage 쓰기·incognito split·다른 프로필 동기화: 프로젝트 내 단일 작성자와 같은 프로필의 공통 설정만 보장한다. 외부 작성자까지 트랜잭션으로 보호하지 않는다.
- 실제 로드 파일 해시·배포·스토어·개인정보 정책 전체 적합성: 설정 코드 검토나 빌드 검사를 전체 인증으로 확대하지 않는다. 개인정보처리방침 브랜치와 URL은 유지하고 외부 게시 작업은 하지 않았다.
